Heimdall Architecture & System Invariants

A compressed systems reference card covering runtime topology, microservice boundaries, safety guarantees, and the Ticket 01 IPC contract.

1. First Principles & Motivation

In production containerized environments, incident triage accounts for 60–80% of Mean-Time-To-Diagnose (MTTD). Engineers manually execute a deterministic diagnostic tree: inspecting container states, reading recent stderr logs, checking network sockets, and analyzing exit codes.

Heimdall decouples probabilistic hypothesis formulation (AI reasoning) from deterministic tool execution & safety gating (compiled systems code).

2. System Topology & Responsibility Matrix

3. Deterministic Safety Risk Tiers

Risk Level Execution Policy Representative Tools
READ_ONLY Auto-approved. Zero state alteration. docker_inspect, docker_logs, net_http_probe
SAFE_WRITE Interactive human confirmation required ([y/N]). docker_restart, systemd_restart
DANGEROUS Explicit confirmation + impact notice. Zero-trust default. docker_stop, docker_remove, unrecognized tools

4. Ticket 01 IPC Contract Breakdown

Implemented in proto/v1/agent_service.proto:

  • Unary Turn Model: rpc DecideNextStep (DecideRequest) returns (DecideResponse); ensures Python remains stateless while Go maintains the authoritative session history.
  • Polymorphic Tool Schemas: json_schema and arguments_json are serialized JSON strings. Tools can be added, updated, or deprecated in Go without recompiling protobuf definitions.
  • ReAct Decomposition: DecideResponse isolates internal reasoning (thought) from actions (requested_tool_calls) and resolution (final_answer, is_final_answer).
